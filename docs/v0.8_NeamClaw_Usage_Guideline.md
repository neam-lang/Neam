## 1. Architecture Overview

NeamClaw introduces two purpose-built agent primitives on top of the Neam
runtime.  **Claw agents** hold long-running conversations with session
persistence, multi-channel I/O, and automatic context compaction.  **Forge
agents** run iterative build-verify loops that checkpoint work and track
progress against a plan.

```
 ┌──────────────────────────────────────────────────────────────────┐
 │                       Neam Source (.neam)                        │
 │                                                                  │
 │  skill, guard, guardchain, struct, trait, sealed, agent,         │
 │  claw agent, forge agent, channel, impl, fun, ...               │
 └─────────────────────────────┬────────────────────────────────────┘
                               │  neamc (compiler)
                               ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │                      Bytecode (.neamb)                           │
 └─────────────────────────────┬────────────────────────────────────┘
                               │  neam / neam-api / neam-forge
                               ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │                     Virtual Machine (VM)                         │
 │                                                                  │
 │  ┌─────────────┐  ┌──────────────┐  ┌──────────────────────┐    │
 │  │ Claw Agents  │  │ Forge Agents │  │ Legacy Agents (v0.6) │    │
 │  │             │  │              │  │                      │    │
 │  │ .ask()      │  │ .run()       │  │ .ask()               │    │
 │  │ .reset()    │  │ .ask()       │  └──────────────────────┘    │
 │  │ .history()  │  │ .reset()     │                              │
 │  └──────┬──────┘  └──────┬───────┘                              │
 │         │                │                                      │
 │  ┌──────▼────────────────▼──────────────────────────────────┐   │
 │  │           LLM Provider Layer (OpenAI / Ollama / Bedrock) │   │
 │  └──────────────────────────────────────────────────────────┘   │
 │                                                                  │
 │  ┌────────────┐ ┌──────────┐ ┌──────────┐ ┌────────────────┐   │
 │  │ Sessions   │ │ Channels │ │ Memory   │ │ DAG Executor   │   │
 │  │ (JSONL)    │ │ CLI/HTTP │ │ BM25+Vec │ │ spawn / dag    │   │
 │  └────────────┘ └──────────┘ └──────────┘ └────────────────┘   │
 └──────────────────────────────────────────────────────────────────┘
```

## 2. Agent Types at a Glance

| Feature | `agent` (legacy) | `claw agent` | `forge agent` |
|---------|:---------:|:------------:|:-------------:|
| LLM calls | Single-turn | Multi-turn with sessions | Iterative loop |
| Session persistence | No | JSONL on disk | No |
| Context compaction | No | Auto / manual | No |
| Tool-calling loop | Yes | Yes (up to 25 steps) | Yes (up to 25 steps) |
| Verify callback | No | No | Yes |
| Checkpoint | No | No | git / snapshot / none |
| Channels | No | CLI / HTTP | No |
| Lanes (concurrency) | No | Yes | No |
| Semantic memory | No | BM25 + vector | No |
| Workspace I/O | No | Yes | Yes |
| Plan tracking | No | No | Yes (plan + progress) |
| Built-in trait support | Partial | Full (6 traits) | Full (6 traits) |

### When to Use Which

```
 Need persistent conversations?
 │
 ├── YES ──▶  claw agent
 │            (customer support, chat assistants, tutors)
 │
 └── NO
     │
     Need iterative build-verify with checkpoints?
     │
     ├── YES ──▶  forge agent
     │            (code generators, document builders, data pipelines)
     │
     └── NO ──▶  agent (legacy)
                  (simple single-turn tasks, RAG queries)
```

## 3. Claw Agents — Conversational Agents

### 3.1 Declaration Syntax

```neam
claw agent <name> {
  // ── Required ─────────────────────────────────
  provider: "<provider>"           // "openai" | "ollama" | "bedrock"
  model: "<model_id>"             // "gpt-4o" | "llama3" | etc.
  channels: [<channel_ref>, ...]  // Must be non-empty

  // ── Identity ─────────────────────────────────
  system: "<system_prompt>"       // Instructions for the LLM
  temperature: <0.0 - 2.0>       // Default: 0.0

  // ── Connection ───────────────────────────────
  endpoint: "<url>"               // Custom LLM endpoint
  api_key_env: "<ENV_VAR>"        // Env var holding API key

  // ── Capabilities ─────────────────────────────
  skills: [<skill_ref>, ...]      // Tools the agent can call
  guards: [<guardchain_ref>]      // Security guard chains
  connected_knowledge: [<kb_ref>] // RAG knowledge bases

  // ── Session Config ───────────────────────────
  session: {
    idle_reset_minutes: <int>     // Default: 60  (reset after N min idle)
    daily_reset_hour: <int>       // Default: 4   (daily reset at 4 AM)
    max_history_turns: <int>      // Default: 100 (keep last N turns)
    compaction: "<mode>"          // "auto" | "manual" | "disabled"
  }

  // ── Workspace ────────────────────────────────
  workspace: "<path>"             // Filesystem root for sessions + files

  // ── Channels & Lanes ─────────────────────────
  lanes: {
    <lane_name>: {
      concurrency: <int>          // Default: 1
      priority: "<str>"           // Default: "normal"
    }
  }

  // ── Semantic Memory ──────────────────────────
  semantic_memory: {
    backend: "<str>"              // "sqlite" | "local" | "none"
    search: "<str>"               // "hybrid" | "vector" | "keyword" | "none"
    flush_on_compact: true|false  // Default: false
  }
}
```

### 3.2 Minimal Claw Agent

```neam
skill greet {
  description: "Greet the user"
  params: { name: string }
  impl(name) {
    return "Hello, " + name + "!";
  }
}

claw agent assistant {
  provider: "openai"
  model: "gpt-4o"
  channels: [greet]
  system: "You are a helpful assistant."
}
```

### 3.3 The `.ask()` Flow

When you call `assistant.ask("What is Neam?")`, this is the full pipeline:

```
 ┌──────────────────────────────────────────────────────────────┐
 │                     claw.ask(query)                          │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 1. SECURITY CHECKS                                          │
 │    ├── Recursion depth guard (max_agent_depth)               │
 │    └── Kill switch (BehavioralMonitor.is_disabled)           │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 2. SESSION MANAGEMENT                                       │
 │    ├── SessionManager.get_or_create(agent, "default")       │
 │    └── SessionManager.append_message("user", query)         │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 3. CONTEXT BUILDING                                         │
 │    ├── ContextBuilder.build(agent, session)                  │
 │    │   ├── system prompt                                    │
 │    │   ├── last N turns (respects max_history_turns)        │
 │    │   └── token budget (128K default, chars/4 estimate)    │
 │    │                                                        │
 │    ├── AUTO-COMPACTION (if compaction == "auto")             │
 │    │   └── If >80% context budget used:                     │
 │    │       summarize oldest 2/3 of history via LLM          │
 │    │                                                        │
 │    └── MEMORY INJECTION (if semantic_memory.search != none) │
 │        └── Top 3 results appended to system prompt          │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 4. TOOL-CALLING LOOP (up to 25 iterations)                  │
 │                                                              │
 │    ┌──────────────────────────────────────┐                  │
 │    │  provider.chat_with_tools(messages,  │◀──┐              │
 │    │    tool_defs, "auto")                │   │              │
 │    └──────────────┬───────────────────────┘   │              │
 │                   │                           │              │
 │         ┌─────────▼──────────┐                │              │
 │         │ Tool calls?        │                │              │
 │         ├── YES: execute     ├────────────────┘              │
 │         │   each tool call   │                               │
 │         │                    │                               │
 │         └── NO: final        │                               │
 │             response ────────▶ break                         │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 5. RESPONSE                                                  │
 │    ├── Append assistant message to session                   │
 │    ├── Record behavioral metrics                             │
 │    └── Return response string                                │
 └──────────────────────────────────────────────────────────────┘
```

### 3.4 Methods Reference

| Method | Returns | Description |
|--------|---------|-------------|
| `agent.ask(query)` | String | Full session-aware LLM call with tool loop |
| `agent.reset()` | nil | Clears session history (both manager and context) |
| `agent.history()` | List of `{role, content}` maps | Returns conversation history |

```neam
let name     = my_agent.name;               // String

let model    = my_agent.model;               // String
```

## 4. Forge Agents — Build-Verify Agents

### 4.1 Declaration Syntax

```neam
forge agent <name> {
  // ── Required ─────────────────────────────────
  provider: "<provider>"
  model: "<model_id>"
  verify: <function_ref>          // fun(ctx) -> bool | nil | string

  // ── Identity ─────────────────────────────────
  system: "<system_prompt>"
  temperature: <number>

  // ── Connection ───────────────────────────────
  endpoint: "<url>"
  api_key_env: "<ENV_VAR>"

  // ── Capabilities ─────────────────────────────
  skills: [<skill_ref>, ...]
  guards: [<guardchain_ref>]

  // ── Loop Config ──────────────────────────────
  loop: {
    max_iterations: <int>         // Default: 25
    max_cost: <number>            // Default: 10.0
    max_tokens: <int>             // Default: 500000
    prompt_file: "<path>"         // External system prompt file
    plan_file: "<path>"           // One task per line
    progress_file: "<path>"       // JSONL: completed tasks
    learnings_file: "<path>"      // JSONL: append-only log
  }

  // ── Checkpoint ───────────────────────────────
  checkpoint: "<strategy>"        // "git" | "snapshot" | "none"

  // ── Workspace ────────────────────────────────
  workspace: "<path>"
}
```

### 4.2 The `.run()` Flow

```
 ┌──────────────────────────────────────────────────────────────┐
 │                     forge.run()                              │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 1. SETUP                                                     │
 │    ├── Security checks (depth guard + kill switch)           │
 │    ├── Create LLM provider                                   │
 │    ├── Load plan_file tasks (one per line)                   │
 │    ├── Load progress_file (skip completed tasks)             │
 │    └── Load prompt_file (additional system context)          │
 └──────────┬───────────────────────────────────────────────────┘
            │
 ┌──────────▼───────────────────────────────────────────────────┐
 │ 2. MAIN LOOP (iteration = 1 to max_iterations)              │
 │                                                              │
 │    ┌──────────────────────────────────────────────────────┐  │
 │    │  Budget check: total_cost >= max_cost?               │  │
 │    │  └── YES: return {outcome: "budget_exhausted"}       │  │
 │    └────────────────────┬─────────────────────────────────┘  │
 │                         │                                    │
 │    ┌────────────────────▼─────────────────────────────────┐  │
 │    │  Build messages:                                     │  │
 │    │    system + prompt_file + iteration prompt            │  │
 │    │    + current_task + previous_feedback                 │  │
 │    └────────────────────┬─────────────────────────────────┘  │
 │                         │                                    │
 │    ┌────────────────────▼─────────────────────────────────┐  │
 │    │  LLM + Tool Loop (same as claw, up to 25 steps)     │  │
 │    └────────────────────┬─────────────────────────────────┘  │
 │                         │                                    │
 │    ┌────────────────────▼─────────────────────────────────┐  │
 │    │  VERIFY: call verify_fn(loop_context)                │  │
 │    │                                                      │  │
 │    │  ┌─ true ──────▶ Verified!                           │  │
 │    │  │                ├── checkpoint(strategy)            │  │
 │    │  │                ├── mark_task_done(progress_file)   │  │
 │    │  │                ├── append_learning("completed")    │  │
 │    │  │                └── advance to next task            │  │
 │    │  │                                                   │  │
 │    │  ├─ false/nil ──▶ Not verified, retry                │  │
 │    │  │                └── feedback = "Verification failed"│  │
 │    │  │                                                   │  │
 │    │  ├─ "abort" ────▶ Abort loop                         │  │
 │    │  │                └── return {outcome: "aborted"}     │  │
 │    │  │                                                   │  │
 │    │  └─ "retry"|str ▶ Not verified, retry with feedback  │  │
 │    │                   └── feedback = <returned string>    │  │
 │    └──────────────────────────────────────────────────────┘  │
 │                                                              │
 │    Loop continues until:                                     │
 │      • All tasks completed → {outcome: "completed"}          │
 │      • max_iterations hit  → {outcome: "max_iterations"}     │
 │      • Budget exhausted    → {outcome: "budget_exhausted"}   │
 │      • Verify aborts       → {outcome: "aborted"}           │
 └──────────────────────────────────────────────────────────────┘
```

### 4.3 The Verify Callback

The verify function receives a `LoopContext` object and controls the loop:

```neam
fun my_verify(ctx) {
  // ctx.iteration     → current iteration number (int)
  // ctx.current_task  → current plan task (string)
  // ctx.feedback      → previous feedback (string)
  // ctx.total_cost    → cost so far (number)
  // ctx.total_tokens  → tokens so far (int)

  // Return values and their effects:
  //   true           → Verified. Checkpoint + next task.
  //   false / nil    → Retry. Feedback = "Verification failed"
  //   "abort"        → Stop the loop immediately.
  //   "retry"        → Retry. Feedback = "retry"
  //   "<any string>" → If contains "abort", abort. Otherwise, verified.

  if (ctx.iteration > 3) {
    return "abort";
  }
  return true;
}
```

### 4.4 Return Value (LoopOutcome)

`.run()` returns a Neam map:

```neam
let result = my_forge.run();

result.outcome      // "completed" | "max_iterations" | "aborted" | "budget_exhausted"
result.iterations   // Number: how many iterations ran
result.total_cost   // Number: estimated cost
result.message      // String: description of outcome
```

| Strategy | Behavior |
|----------|----------|

| `"none"` | No checkpointing (default if omitted) |

## 5. Sessions & Context Management

### 5.1 How Sessions Work

Every claw agent maintains sessions — keyed conversations that persist to disk.

```
 ┌──────────────────────────────────────────────────────────────┐
 │                    Session Lifecycle                          │
 │                                                              │
 │  .ask("Hello")         .ask("Follow up")     .reset()       │
 │       │                      │                   │           │
 │  ┌────▼──────────────────────▼───────────────────▼────────┐  │
 │  │                  SessionManager                        │  │
 │  │                                                        │  │
 │  │  get_or_create() ──▶ append_message("user", ...)      │  │
 │  │                      append_message("assistant", ...)  │  │
 │  │                      load_history() ──▶ [role,content] │  │
 │  │                      compact(summary, keep_recent=20)  │  │
 │  │                      reset() ──▶ archive + clear       │  │
 │  └────────────────────────┬───────────────────────────────┘  │
 │                           │                                  │
 │  ┌────────────────────────▼───────────────────────────────┐  │
 │  │  Disk (workspace/sessions/)                            │  │
 │  │                                                        │  │
 │  │  sessions_index.json                                   │  │
 │  │  session_abc123.jsonl                                  │  │
 │  │    {"role":"user","content":"Hello"}                   │  │
 │  │    {"role":"assistant","content":"Hi there!"}          │  │
 │  │    {"role":"user","content":"Follow up"}               │  │
 │  │    {"role":"assistant","content":"Sure, here..."}      │  │
 │  └────────────────────────────────────────────────────────┘  │
 └──────────────────────────────────────────────────────────────┘
```

### 5.2 Context Building

The `ContextBuilder` assembles messages for the LLM, respecting token budgets:

```
 ┌────────────────────────────────────────────────────────────┐
 │                   ContextBuilder.build()                    │
 │                                                            │
 │  Input:                                                    │
 │    ├── agent.system          "You are a support agent"     │
 │    ├── session.history       [(user, "Q1"), (asst, "A1"),  │
 │    │                          (user, "Q2"), (asst, "A2"),  │
 │    │                          (user, "Q3")]                │
 │    └── max_context_tokens    128000                        │
 │                                                            │
 │  Output (AssembledContext):                                │
 │    ├── system_prompt         "You are a support agent"     │
 │    ├── messages              [(user,"Q1"),(asst,"A1"),...] │
 │    ├── token_estimate        ~500                          │
 │    └── was_truncated         false                         │
 │                                                            │
 │  Rules:                                                    │
 │    • Respects max_history_turns (default: 100)             │
 │    • Token budget: chars/4 heuristic                       │
 │    • Oldest messages dropped first if over budget          │
 └────────────────────────────────────────────────────────────┘
```

### 5.3 Auto-Compaction

When `compaction: "auto"` is set (the default), the engine automatically
compresses history when the context budget fills up:

```
 Before compaction:                After compaction:
 ─────────────────                 ──────────────────
 [system prompt]                   [system prompt]
 user: Q1                          assistant: [Summary of Q1-Q8 and
 assistant: A1                       their answers. Key topics were
 user: Q2                            X, Y, and Z...]
 assistant: A2                     user: Q9
 ...                               assistant: A9
 user: Q8        ─── LLM ──▶      user: Q10    (keep_recent = 20)
 assistant: A8     summarize       assistant: A10
 user: Q9                          user: Q11
 assistant: A9
 user: Q10
 assistant: A10
 user: Q11

 Token usage: ~80% of budget       Token usage: ~35% of budget
```

- **Trigger**: Context exceeds 80% of max tokens (128K default)
- **Strategy**: Oldest 2/3 of turns → LLM summary → single message
- **Configurable**: `keep_recent` defaults to 20 turns

### 5.4 Session Config Defaults

| Field | Default | Description |
|-------|---------|-------------|
| `idle_reset_minutes` | `60` | Reset session after N minutes of inactivity |
| `daily_reset_hour` | `4` | Daily reset at this hour (0-23) |
| `max_history_turns` | `100` | Maximum turns to keep in context |
| `compaction` | `"auto"` | `"auto"`, `"manual"`, or `"disabled"` |

### 6.4 Lanes — Concurrent Processing

Lanes partition work within a claw agent for concurrent processing:

```neam
claw agent support_bot {
  provider: "openai"
  model: "gpt-4o"
  channels: [cli_chan]
  lanes: {
    main: { concurrency: 4, priority: "normal" }
    vip:  { concurrency: 2, priority: "high" }
  }
}
```

```
 ┌─────────────────────────────────────────────────────┐
 │                  LaneQueueEngine                     │
 │                                                     │
 │  Lane: "main" (concurrency: 4)                      │
 │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐               │
 │  │ W1   │ │ W2   │ │ W3   │ │ W4   │  4 workers    │
 │  └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘               │
 │     └────────┴────────┴────────┘                    │
 │                    ▲                                 │
 │            ┌───────┴───────┐                        │
 │            │ Pending Queue │                        │
 │            └───────────────┘                        │
 │                                                     │
 │  Lane: "vip" (concurrency: 2, priority: "high")    │
 │  ┌──────┐ ┌──────┐                                 │
 │  │ W1   │ │ W2   │  2 workers                      │
 │  └──┬───┘ └──┬───┘                                 │
 │     └────────┘                                      │
 │          ▲                                          │
 │   ┌──────┴──────┐                                   │
```

## 7. Semantic Memory & Workspace I/O

### 7.1 Workspace

The `workspace` field defines a filesystem root for agent-specific file I/O:

```neam
claw agent my_agent {
  provider: "openai"
  model: "gpt-4o"
  channels: [my_chan]
  workspace: "./agent_data"
}
```

### 7.2 Native File Functions

| Function | Signature | Description |
|----------|-----------|-------------|
| `workspace_read(path)` | `(string) -> string\|nil` | Read file content. Rejects `..` paths. |
| `workspace_write(path, content)` | `(string, string) -> bool` | Write content (truncate). Creates parent dirs. |
| `workspace_append(path, content)` | `(string, string) -> bool` | Append to file. Creates if missing. |

```neam
// Write a file
workspace_write("notes/meeting.txt", "Meeting notes here...");

// Read it back
let content = workspace_read("notes/meeting.txt");

// Append to a log
workspace_append("logs/activity.log", "User logged in\n");
```

**Security**: All paths are resolved relative to the workspace and validated
against path traversal. Any path containing `..` is rejected outright.

### 7.3 Semantic Memory

Configure memory search to give the agent recall across conversations:

```neam
claw agent recall_bot {
  provider: "openai"
  model: "gpt-4o"
  channels: [my_chan]
  workspace: "./data"
  semantic_memory: {
    backend: "local"
    search: "hybrid"      // BM25 + vector cosine
    flush_on_compact: false
  }
}
```

### 7.4 Memory Search Architecture

```
 ┌──────────────────────────────────────────────────────────────┐
 │                      MemoryIndex                             │
 │                                                              │
 │  workspace/                                                  │
 │  ├── file1.txt ──┐                                          │
 │  ├── file2.md  ──┤  index_workspace()                       │
 │  └── notes/ ─────┘     │                                    │
 │                         ▼                                    │
 │  ┌──────────────────────────────────────┐                   │
 │  │  Chunking (400 chars, 80 overlap)    │                   │
 │  └──────────────┬───────────────────────┘                   │
 │                 │                                            │
 │    ┌────────────▼────────────┐                              │
 │    │  MemoryChunk[]          │                              │
 │    │  { file_path, text,     │                              │
 │    │    chunk_index }        │                              │
 │    └────────────┬────────────┘                              │
 │                 │                                            │
 │   ┌─────────────┼──────────────┐                            │
 │   ▼             ▼              ▼                            │
 │ ┌──────┐   ┌────────┐   ┌──────────┐                       │
 │ │ BM25 │   │ Vector │   │ Hybrid   │  ← search mode        │
 │ │ Index │   │ Index  │   │ (both)   │                       │
 │ └──┬───┘   └───┬────┘   └────┬─────┘                       │
 │    └────────────┼─────────────┘                             │
 │                 ▼                                            │
 │  search(query, top_k=5) → [{ file_path, chunk, score }]    │
 └──────────────────────────────────────────────────────────────┘
```

### 7.5 Memory Search Native

```neam
// Search indexed workspace
let results = memory_search("authentication flow");

// With custom top_k
let results = memory_search("authentication flow", 10);

// Each result is a map:
// { "file_path": "docs/auth.md", "chunk": "...", "score": 0.85 }
```

### 7.6 Session History Native

```neam
// Get all history for default session
let hist = session_history();

// Get specific session, last 10 turns
let hist = session_history("user_123", 10);

// Each entry: { "role": "user"|"assistant", "content": "..." }
```

### 7.7 Automatic Memory Injection

When a claw agent has `semantic_memory.search` configured (not `"none"`),
every `.ask()` call automatically:

1. Searches the memory index with the user's query (top 3 results)
2. Prepends matching context to the system prompt:

```
[Relevant memory context]
- docs/auth.md: "The authentication module uses JWT tokens..."
- src/login.neam: "The login flow validates credentials then..."
- notes/design.md: "Session tokens expire after 24 hours..."
```

## 9. Multi-Agent Orchestration

### 9.1 The `spawn` Keyword

Invoke another agent by name from within your code:

```neam
// Keyword form — static agent name
let result = spawn researcher("Find recent papers on RAG");

// Native function form — dynamic agent name
let agent_name = "researcher";
let result = spawn(agent_name, "Find recent papers on RAG");
```

### 9.2 Spawn Resolution Order

```
 spawn <name>(task)
       │
       ▼
 ┌─────────────────────────────┐
 │ 1. Check claw_agents_       │──▶ Single-turn LLM → string
 │                             │
 │ 2. Check forge_agents_      │──▶ Single-turn LLM → outcome map
 │                             │
 │ 3. Check globals_ (legacy)  │──▶ Single-turn LLM → string
 │                             │
 │ 4. Not found                │──▶ "Agent not found: <name>"
 └─────────────────────────────┘
```

**Note**: `spawn` does a simplified single-turn LLM call. It does NOT invoke
the full `.ask()` session flow or the full `.run()` forge loop. Use
`agent.ask()` or `agent.run()` directly for full behavior.

### 9.3 DAG Execution

Execute a directed acyclic graph of agent tasks with dependency ordering:

```neam
let results = dag_execute([
  {
    "id": "research",
    "agent": "researcher",
    "task": "Gather data on market trends",
    "depends_on": []
  },
  {
    "id": "analysis",
    "agent": "analyst",
    "task": "Analyze the research findings",
    "depends_on": ["research"]
  },
  {
    "id": "report",
    "agent": "writer",
    "task": "Write executive summary",
    "depends_on": ["research", "analysis"]
  }
]);

// results is a Map: { "research": "...", "analysis": "...", "report": "..." }
```

### 9.4 DAG Execution Flow

```
 dag_execute(nodes)
       │
       ▼
 ┌─────────────────────────────────────────┐
 │  Kahn's Topological Sort                │
 │                                         │
 │  research ──▶ analysis ──▶ report       │
 │      └───────────────────────┘          │
 └──────────────┬──────────────────────────┘
                │
                ▼
 Sequential execution in dependency order:

 Step 1: spawn("researcher", "Gather data...")
         └── result stored as results["research"]

 Step 2: spawn("analyst", "Analyze findings...")
         └── result stored as results["analysis"]

 Step 3: spawn("writer", "Write summary...")
         └── result stored as results["report"]

 Return: { "research": "...", "analysis": "...", "report": "..." }
```

### 9.5 DagNode Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | String | Yes | Unique node identifier |
| `agent` | String | Yes | Name of agent to invoke |
| `task` | String | No | Task description passed to agent |
| `depends_on` | List of strings | No | IDs of nodes that must complete first |

### 9.6 Orchestrable Callbacks

When a spawning agent implements `Orchestrable`, callbacks fire automatically:

```
 spawn researcher("task")
       │
       ├── Orchestrable.on_spawn("researcher")    ← before LLM call
       │
       ├── LLM completes...
       │
       └── Orchestrable.on_delegate(result)        ← after result
```

## 11. neam-forge CLI

Run forge agents directly from the command line.

### 11.1 Usage

```bash
neam-forge --agent <file.neam> [options]
```

### 11.2 Flags

| Flag | Required | Description |
|------|----------|-------------|
| `--agent FILE` | **Yes** | Path to .neam file containing forge agent(s) |
| `--name NAME` | No | Specific forge agent name (default: first found) |
| `--workspace DIR` | No | Override the agent's workspace directory |
| `--max-iterations N` | No | Override max iterations |
| `--max-cost N` | No | Override max cost limit |
| `--verbose` | No | Print compile/agent details to stderr |
| `--help` | No | Show help |

### 11.3 Example

```bash
# Run with defaults
neam-forge --agent build_pipeline.neam

# Override workspace and iteration limit
neam-forge --agent build_pipeline.neam \
  --workspace ./output \
  --max-iterations 10 \
  --verbose

# Run a specific named agent from a file with multiple forge agents
neam-forge --agent agents.neam --name code_builder
```

### 11.4 Output

The CLI prints the LoopOutcome map:

```
{outcome: "completed", iterations: 7, total_cost: 0.0042, message: "All tasks completed"}
```

Exit codes:
- `0` — forge loop completed successfully
- `1` — error (compilation, missing agent, runtime error)

### 11.5 How It Works

```
 neam-forge --agent my_file.neam --name builder
       │
       ├── 1. Read & compile my_file.neam
       │
       ├── 2. Execute bytecode on fresh VM
       │      (registers agents, skills, structs)
       │
       ├── 3. Find forge agent "builder" in vm.forge_agents()
       │
       ├── 4. Apply CLI overrides (--workspace, --max-iterations, etc.)
       │
       ├── 5. Generate wrapper: "let result = builder.run(); emit result;"
       │
       ├── 6. Compile + execute wrapper on same VM
       │
       └── 7. Print emitted LoopOutcome map
```

```neam
    emit "ALERT: anomaly on support_bot: " + event;
    return nil;
  }
}

// interact
let r1 = support_bot.ask("What is the status of order ORD-12345?");
emit r1;

let r2 = support_bot.ask("And when will it arrive?");
emit r2;   // The agent remembers the context from r1
```

```neam
// skills
skill write_file {
  description: "Write content to a file"
  params: { path: string, content: string }

    workspace_write(path, content);
    return "Wrote " + path;
  }

  description: "Read a file"

  impl(path) {
    return workspace_read(path);
  }

guard safe_guard {
  description: "Safety guard"
  on_observation(text) { return text; }
}

guardchain code_safety = [safe_guard];

// verify function
fun verify_code(ctx) {
  // Check if main file was created
  let main = workspace_read("src/main.py");
  if (main == nil) {
    return "retry";   // Retry: main.py not created yet
  }

  // Check if tests exist
  let tests = workspace_read("tests/test_main.py");
  if (tests == nil) {
    return "No tests found. Please create tests/test_main.py";
  }

  return true;   // All checks pass
}

// the agent
forge agent code_builder {
  provider: "openai"
  model: "gpt-4o"
  system: "You are an expert Python developer. Write clean, tested code."
  skills: [write_file, read_file]
  guards: [code_safety]
  verify: verify_code
  workspace: "./generated_code"
  checkpoint: "git"

  loop: {
    max_iterations: 10
    max_cost: 5.0
    plan_file: "plan.md"
    progress_file: "progress.jsonl"
    learnings_file: "learnings.jsonl"
  }
}

let outcome = code_builder.run();
```

### 13.3 Multi-Agent Pipeline

```neam
// Three agents working together
skill web_search {
  description: "Search the web"
  params: { query: string }
  impl(query) {
    return "Search results for: " + query;
  }

guard safety {
  description: "Input guard"

}

guardchain safe_chain = [safety];

claw agent researcher {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a research assistant. Gather and summarize information."
  skills: [web_search]
  guards: [safe_chain]
  channels: [web_search]
}

claw agent analyst {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a data analyst. Analyze information and find patterns."
  skills: [web_search]
  guards: [safe_chain]
  channels: [web_search]
}

claw agent writer {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a technical writer. Create clear, well-structured reports."
  skills: [web_search]
  guards: [safe_chain]
  channels: [web_search]
}

// Orchestration callbacks
impl Orchestrable for researcher {
  fn on_spawn(self, child) {
    emit "Researcher spawned: " + child;
    return nil;
  }
  fn on_delegate(self, result) {
    emit "Researcher got delegation result";
    return nil;
  }
}

// DAG execution: research → analysis → report
let results = dag_execute([
  {
    "id": "gather",
    "agent": "researcher",
    "task": "Research recent advances in AI agent frameworks",
    "depends_on": []
  },
  {
    "id": "analyze",
    "agent": "analyst",
    "task": "Identify key trends and compare frameworks",
    "depends_on": ["gather"]
  },
  {
    "id": "write",
    "agent": "writer",
    "task": "Write a 500-word executive summary",
    "depends_on": ["gather", "analyze"]
  }
]);

emit "Research: " + results["gather"];
emit "Analysis: " + results["analyze"];
emit "Report: " + results["write"];
```

### Methods Quick Reference

```
 Claw:                          Forge:
   .ask(query) → string           .run() → {outcome, iterations, ...}
   .reset()    → nil              .ask(query) → string
   .history()  → [{role,content}] .reset()    → nil

 Orchestration:
   spawn agent_name(task)        → string | outcome map
   spawn("name", task)           → string | outcome map
   dag_execute([nodes])          → {id: result, ...}

 Workspace:
   workspace_read(path)          → string | nil
   workspace_write(path, text)   → bool
   workspace_append(path, text)  → bool

 Memory:
   memory_search(query [, k])    → [{file_path, chunk, score}]
   session_history([key [, n]])  → [{role, content}]
```

### Verify Return Values

```
 Return        Effect
 ──────        ──────
 true          Verified → checkpoint → next task
 false / nil   Not verified → retry (feedback: "Verification failed")
 "abort"       Abort loop → {outcome: "aborted"}
 "retry"       Not verified → retry (feedback: "retry")
 "<string>"    If has "abort" → abort; else → verified
```
