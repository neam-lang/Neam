## 1. Architecture Overview

### How Neam Works — The Big Picture

```
 DEVELOPER WRITES              NEAM COMPILES               NEAM SERVES
 ==================           ==============              ============

  +----------------+      +------------------+      +-------------------+
  |  main.neam     |      |     neamc        |      |    neam-api       |
  |                |----->|   (compiler)     |----->|  (HTTP server)    |
  |  agent Coder { |      |                  |      |                   |
  |    provider:.. |      | parse -> AST     |      |  /api/v1/agent/ask|
  |    model: ...  |      | typecheck        |      |  /api/v1/agents   |
  |    skills: ... |      | codegen -> .neamb|      |  /api/v1/health   |
  |  }             |      |                  |      |  /health          |
  +----------------+      +------------------+      |  /ready           |
                                                    +-------------------+
                                                           |
                                                     JIT per request
                                                           |
                                                    +------v--------+
                                                    |   Neam VM     |
                                                    |  +----------+ |
                                                    |  | Agent    | |
                                                    |  | LLM call | |
                                                    |  | Skills   | |
                                                    |  | Guards   | |
                                                    |  +----------+ |
                                                    +---------------+
```

### Request Lifecycle — From HTTP to Agent Response

```
    Client                   neam-api                  Neam VM                   LLM Provider
      |                         |                         |                          |
      |  POST /api/v1/agent/ask |                         |                          |
      |  { agent: "Coder",      |                         |                          |
      |    message: "..." }     |                         |                          |
      |------------------------>|                         |                          |
      |                         |                         |                          |
      |                         |  pipeline.compile()     |                          |
      |                         |  (JIT compile .neam)    |                          |
      |                         |------------------------>|                          |
      |                         |                         |                          |
      |                         |                         |  POST /v1/chat/completions
      |                         |                         |  (with tools array)      |
      |                         |                         |------------------------->|
      |                         |                         |                          |
      |                         |                         |  tool_call: calculate()  |
      |                         |                         |<-------------------------|
      |                         |                         |                          |
      |                         |                         |  [execute skill locally] |
      |                         |                         |  return tool result      |
      |                         |                         |------------------------->|
      |                         |                         |                          |
      |                         |                         |  final text response     |
      |                         |    VM result            |<-------------------------|
      |                         |<------------------------|                          |
      |                         |                         |                          |
      |  { response: "..." }    |                         |                          |
      |<------------------------|                         |                          |
```

### Deployment Architecture — Where neam-api Runs

```
                        +---------------------------+
                        |   neamc deploy --target   |
                        |   (artifact generator)    |
                        +-------------+-------------+
                                      |
                 +--------------------+--------------------+
                 |                    |                     |
                 v                    v                     v
     +-----------+------+  +---------+--------+  +---------+---------+
     |     Docker       |  |  AWS EKS (K8s)   |  |   AWS Lambda      |
     |                  |  |                   |  |                    |
     | +------+  .neam  |  |  +-----+  .neam  |  |  Lambda Web       |
     | |neam- |  src/   |  |  |neam-|  src/   |  |  Adapter           |
     | | api  |  neam.  |  |  | api |  neam.  |  |  +-----+  .neam   |
     | |:8080 |  toml   |  |  |:8080|  toml   |  |  |neam-|  src/    |
     | +------+         |  |  +-----+         |  |  | api |  neam.   |
     |                  |  |  Pods x replicas  |  |  |:8080|  toml    |
     | docker run       |  |  ALB ingress     |  |  +-----+          |
     | -p 8080:8080     |  |  HPA autoscale   |  |  API GW -> Lambda |
     +-----------+------+  +---------+--------+  +--------+----------+
                 |                    |                     |
                 +--------------------+---------------------+
                                      |
                               Same .neam source
                               Same neam-api binary
                               Zero code changes
```

### JIT Compilation — Why Agent Logic Stays in Source

```
                   +---------------------------------------------------+
                   |                 Docker Container                   |
                   |                                                   |
                   |  /usr/local/bin/neam-api    (HTTP server binary)  |
                   |  /usr/local/bin/neamc       (compiler binary)     |
                   |  /usr/local/share/neam/stdlib/  (standard lib)    |
                   |                                                   |
                   |  /app/neam.toml             (project config)      |
                   |  /app/src/main.neam         (YOUR agent source)   |
                   |  /app/src/api.neam          (YOUR API routes)     |
                   |                                                   |
                   |  neam-api starts -> reads neam.toml               |
                   |       on each request:                            |
                   |       1. pipeline.compile(src/main.neam)          |
                   |       2. VM executes agent logic                  |
                   |       3. Agent calls LLM provider                 |
                   |       4. Skills execute locally in VM             |
                   |       5. Returns HTTP response                    |
                   +---------------------------------------------------+

    KEY INSIGHT: Your .neam source files ship IN the container.
    neam-api compiles them at request time (JIT).
    Update agent logic = update source files = rebuild container.
    No separate build artifact needed.
```

### Core Building Blocks

```

  |                        NEAM PROGRAM ANATOMY                             |
  |=========================================================================|
  |                                                                         |
  |  +-- Skills (Local Tools) ---------+  +-- External Skills -----------+ |
  |  |  skill calculate {              |  |  extern skill get_weather {  | |
  |  |    description: "..."           |  |    binding: http { ... }     | |
  |  |    params: { expr: string }     |  |  }                          | |
  |  |    impl(expr) { return ...; }   |  |                             | |
  |  |  }                             |  |  extern skill bash_tool {    | |
  |  +---------------------------------+  |    binding: claude_builtin { | |
  |                                       |      type: "bash_20241022"  | |

  |  |  knowledge Docs {               |  |  }                          | |

  |  |    sources: [{ type: "file",    |                                  |
  |  |      path: "./docs.md" }]      |  +-- MCP Servers ---------------+ |
  |  |    retrieval_strategy: "basic"  |  |  mcp_server fs {            | |

  |  |  budget Limit {                 |  +-- Agents -------------------+ |
  |  |    api_calls: 30                |  |  agent Coder {              | |
```

### Skills — Local Tools

```neam
// A skill is a tool the LLM can call. Your impl() runs locally in the VM.

skill calculate {
  description: "Evaluate a mathematical expression"
  params: {
    expression: string
  }
  impl(expression) {
    if (expression == "15 * 23") {
      return "345";
    }
    return "Evaluated: " + expression;
  }
}

skill search_docs {
  description: "Search documentation for a topic"
  params: {
    query: string,
    max_results: number
  }
  impl(query, max_results) {
    return "Found results for: " + query;
  }
}
```

### External Skills — HTTP, MCP, Claude Built-ins

```neam
// HTTP GET binding — parameters interpolated into URL
extern skill get_weather {
  description: "Get current weather for a city"
  params: { city: string }
  binding: http {
    method: "GET"
    url: "https://wttr.in/{city}?format=j1"
    headers: ["Accept: application/json"]
    response_path: "/current_condition/0/weatherDesc/0/value"
    timeout: 5000
  }
}

// HTTP POST binding — parameters sent as JSON body
extern skill create_issue {
  description: "Create a GitHub issue"
  params: { title: string, body: string }
  binding: http {
    method: "POST"
    url: "https://api.github.com/repos/owner/repo/issues"
    headers: [
      "Accept: application/vnd.github.v3+json",
      "Authorization: token ${GITHUB_TOKEN}"
    ]
    timeout: 10000
  }
}

// MCP server — subprocess-based tool provider
mcp_server filesystem {
  command: "npx"
  args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user"]
}

extern skill read_file {
  description: "Read a file from the filesystem"
  params: { path: string }
  binding: mcp {
    server: "filesystem"
    tool: "read_file"
  }
}

// Adopt all tools from an MCP server at once
adopt filesystem.*

// Claude built-in tools
extern skill bash_tool {
  description: "Execute bash commands"
  params: { command: string }
  binding: claude_builtin {
    type: "bash_20241022"
  }
}
```

### Agents — LLM-Powered Entities

```neam
agent CodeReviewer {
  provider: "openai"

  system: "You are a senior code reviewer. Be thorough but constructive."
  skills: [read_file, search_docs, calculate]

// Call an agent
{
```

### Knowledge Bases — RAG

```neam
knowledge ProjectDocs {
  vector_store: "usearch"
  embedding_model: "nomic-embed-text"
  chunk_size: 200
  chunk_overlap: 50
  sources: [
    { type: "file", path: "./docs/architecture.md" },
    { type: "file", path: "./docs/api-reference.md" },
    { type: "web",  path: "https://example.com/docs.md" }
  ]

  mmr_lambda: 0.7

```

### Guards & Budgets — Safety Controls

```neam
guard ContentFilter {
  description: "Filters harmful content"
  on_tool_input(input) {
    if (input == "dangerous") {
      return "block";
    }
    return input;
  }
  on_tool_output(output) {
    return output;
  }
}

guardchain SafetyChain = [ContentFilter];

budget StandardBudget {
  api_calls: 30
  tokens: 200000
}
```

## 6. Agent Development — Full Examples

### Example 1: Customer Support Agent

```neam
// src/main.neam — Customer support agent with tool calling

skill lookup_order {
  description: "Look up order status by order ID"
  params: {
    order_id: string
  }
  impl(order_id) {
    return "Order " + order_id + ": Shipped, arriving in 2 days";
  }
}

skill search_faq {
  description: "Search the FAQ knowledge base"
  params: {
    query: string
  }
  impl(query) {
    return "FAQ result for: " + query;
  }
}

skill escalate_ticket {
  description: "Escalate issue to human support team"
  params: {
    customer_id: string,
    summary: string
  }
  impl(customer_id, summary) {
    return "Ticket created for customer " + customer_id + ": " + summary;
  }
}

knowledge SupportDocs {
  vector_store: "usearch"
  embedding_model: "nomic-embed-text"
  chunk_size: 200
  chunk_overlap: 50
  sources: [
    { type: "file", path: "./docs/returns-policy.md" },
    { type: "file", path: "./docs/shipping-info.md" }
  ]
  retrieval_strategy: "basic"
  top_k: 3
}

guard ProfanityFilter {
  description: "Blocks profane or abusive language"
  on_tool_input(input) {
    return input;
  }
  on_tool_output(output) {
    return output;
  }
}

guardchain SupportGuards = [ProfanityFilter];

budget SupportBudget {
  api_calls: 20
  tokens: 100000
}

agent SupportAgent {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a friendly customer support agent. Help customers with orders, returns, and general questions. Use the tools available to look up information. If you cannot resolve the issue, escalate to the human team."
  skills: [lookup_order, search_faq, escalate_ticket]
  connected_knowledge: [SupportDocs]
  guards: [SupportGuards]
  budget: SupportBudget
}

{
  emit "=== Customer Support Agent Ready ===";
  let response = SupportAgent.ask("Where is my order #12345?");
  emit response;
}
```

### Example 2: Multi-Agent Research Pipeline

```neam
// src/main.neam — Research pipeline with 3 collaborating agents

skill web_search {
  description: "Search the web for information"
  params: { query: string }
  impl(query) {
    return "Search results for: " + query;
  }
}

skill summarize_text {
  description: "Summarize a long text passage"
  params: { text: string }
  impl(text) {
    return "Summary of: " + text;
  }
}

agent Researcher {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a thorough researcher. Find relevant facts and data. Cite your sources."
  skills: [web_search]
}

agent Writer {
  provider: "openai"
  model: "gpt-4o"
  system: "You are an expert technical writer. Transform research into clear, well-structured prose."
  skills: [summarize_text]
}

agent Editor {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a meticulous editor. Check for accuracy, clarity, and completeness. Return the improved version."
}

{
  emit "=== Research Pipeline Started ===";

  // Step 1: Research
  let topic = "How do transformer architectures work in LLMs?";
  emit "Researching: " + topic;
  let research = Researcher.ask("Research this topic thoroughly: " + topic);
  emit "Research complete.";

  // Step 2: Write
  let draft = Writer.ask("Write a technical article based on this research: " + research);
  emit "Draft complete.";

  // Step 3: Edit
  let final_article = Editor.ask("Edit and improve this article: " + draft);
  emit "=== Final Article ===";
  emit final_article;
}
```

### Example 4: Router / Dispatcher Pattern

```neam
// src/main.neam — Intelligent routing to specialized agents

skill calculate {
  description: "Evaluate a math expression"
  params: { expression: string }
  impl(expression) {
    if (expression == "15 * 23") {
      return "345";
    }
    return "Evaluated: " + expression;
  }
}

agent Router {
  provider: "openai"
  model: "gpt-4o-mini"
  system: "Classify the user query into exactly one category: MATH, CODE, GENERAL. Reply with ONLY the category name, nothing else."
}

agent MathExpert {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a mathematics expert. Solve problems step by step."
  skills: [calculate]
}

agent CodeExpert {
  provider: "openai"
  model: "gpt-4o"
  system: "You are a programming expert. Write clean, efficient code."
}

agent GeneralAssistant {
  provider: "openai"
  model: "gpt-4o-mini"
  system: "You are a helpful general assistant."
}

{
  let query = "What is the derivative of x^3 + 2x?";
  emit "Query: " + query;

  let category = Router.ask(query);
  emit "Routed to: " + category;

  if (category == "MATH") {
    let answer = MathExpert.ask(query);
    emit answer;
  }
  if (category == "CODE") {
    let answer = CodeExpert.ask(query);
    emit answer;
  }
  if (category == "GENERAL") {
    let answer = GeneralAssistant.ask(query);
    emit answer;
  }
}
```

### What `ecr-push.sh` Does

```
  ecr-push.sh v1.0.0
  ═══════════════════

     --image-scanning-configuration scanOnPush=true
```

### Architecture Diagram

```
                     Internet
                        |
              +---------v-----------+
              |  API Gateway v2     |
              |  (HttpApi)          |
              |                     |
              |  Routes:            |
              |   GET  /health      |
              |   GET  /ready       |
              |   GET  /api/v1/*    |

              +---------+-----------+
                        |
                        v
              +---------+-----------+
              |  Lambda Function    |
              |  (Container Image)  |
              |  1024 MB / 300s     |
              |                     |
              |  +----------------+ |
              |  | Lambda Web     | |
              |  | Adapter        | |
              |  | (Extension)    | |
              |  +-------+--------+ |
              |          |          |
              |   Converts Lambda   |
              |   events to HTTP    |
              |   requests          |
              |          |          |
              |  +-------v--------+ |
              |  | neam-api       | |
              |  | localhost:8080 | |
              |  | workers: 2    | |
              |  |               | |
              |  | src/main.neam | |
              |  | neam.toml     | |
              |  +---------------+ |
              +---------------------+

  How Lambda Web Adapter Works:
  ═════════════════════════════
  1. Lambda starts container
  2. Web Adapter registers as Lambda Extension
  3. Web Adapter starts neam-api on port 8080
  4. Web Adapter polls GET /health until 200
  5. Lambda invoke arrives (JSON event)
  6. Web Adapter converts event -> HTTP request
  7. Proxies to localhost:8080
  8. neam-api processes request (compile + VM)
  9. Web Adapter converts HTTP response -> Lambda response
  10. API Gateway returns to client
```

## 14. Troubleshooting

### Common Issues

```
  Issue: Docker build fails — "COPY neam-sdk/ ."
  ═══════════════════════════════════════════════
  Cause: neam-sdk/ directory not present in build context.
  Fix:   git clone https://github.com/neam-lang/neam.git neam-sdk
         (must be in project root alongside neam.toml)


  Issue: K8s pods stuck in CrashLoopBackOff
  ═════════════════════════════════════════
  Cause: Missing OPENAI_API_KEY or NEAM_API_KEY in secrets.yaml
  Fix:   kubectl get secret my-agent-secrets -n default -o yaml
         Ensure values are base64-encoded:
         echo -n "sk-your-key" | base64


  Issue: Lambda cold start timeout
  ═══════════════════════════════
  Cause: Neam toolchain compilation on first request takes time.
  Fix:   Increase memory (faster CPU): [deploy.serverless] memory = 2048
         Or increase timeout: [deploy.serverless] timeout = 600


  Issue: ALB health checks failing
  ═══════════════════════════════
  Cause: Health endpoint not responding on the expected path.
  Fix:   neam-api v0.6.8 registers both /health and /api/v1/health.
         Verify: curl http://localhost:8080/health inside the pod.
         Check: ingress.yaml has alb.ingress.kubernetes.io/healthcheck-path: /health


  Issue: CloudFormation "invalid logical ID"
  ══════════════════════════════════════════
  Cause: Hyphens in project name (e.g., "my-agent" -> "my-agentFunction").
  Fix:   v0.6.8 auto-converts to PascalCase: "my-agent" -> "MyAgentFunction".
         If using an older version, avoid hyphens in project name.


  Issue: K8s "invalid name" errors
  ═══════════════════════════════
  Cause: Underscores in project name (e.g., "my_agent").
  Fix:   v0.6.8 auto-sanitizes names: "my_agent" -> "my-agent".
         K8s labels/names only allow lowercase, digits, hyphens, dots.


  Issue: Lambda returns 502 Bad Gateway
  ═════════════════════════════════════
  Cause: Lambda Web Adapter can't reach neam-api on startup.
  Fix:   Check AWS_LWA_PORT matches the --port flag in CMD.
         Check AWS_LWA_READINESS_CHECK_PATH = /health.
         Increase memory if startup is too slow for readiness check.
```

## Summary

Neam v0.6.8 provides a complete cloud deployment pipeline:

```
  neamc new       ->  Scaffold project with deploy config + CI/CD
  neamc build     ->  Compile .neam source
  neamc deploy    ->  Generate production-ready artifacts
  scripts/*.sh    ->  One-command deploy to AWS
  git push --tags ->  Automated CI/CD deployment
```

The same `.neam` source code runs everywhere — Docker, EKS, Lambda — with zero code changes. The `neamc deploy` command generates all the infrastructure artifacts, and the deploy scripts handle the cloud provisioning.
